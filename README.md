# Finance Analytics Tinkoff App

Веб-приложение для отслеживания реального заработка на брокерском счёте Т-Инвестиций + Telegram-бот дивидендных сигналов.

В репозитории два независимых приложения:

| Что | Где | Как запускается |
|---|---|---|
| Finance Tracker — веб-дашборд на Flask | `app.py`, `templates/` | `python app.py` → http://127.0.0.1:5001 |
| Dividend Bot — Telegram-бот по расписанию | `dividend_bot/` | `python main.py` (или `--now`) |

---

## Finance Tracker (веб-приложение)

### Что делает

- Записывает баланс счёта вручную или синхронизирует автоматически через T-Invest API
- Импортирует операции (пополнения и снятия) за последний год из брокерского счёта
- Считает реальный заработок — пополнения и снятия не искажают результат
- Учитывает только торговые дни (пн–пт) при расчёте дневного заработка
- Показывает статистику за неделю, месяц и за всё время с учётом налога 13%
- График заработка по дням за последние 30 дней
- Годовой график с заработком, заработком после налога и доходностью по методу Modified Dietz
- График нереализованного P&L по позициям портфеля (из T-Invest API)
- График ценовой доходности топ-5 акций по месяцам (из свечей T-Invest API)
- Записывает снятия и пополнения вручную с расчётом комиссии

### Как считается заработок

Между двумя соседними записями баланса:

```
заработок = (баланс₂ − баланс₁) + снятия − пополнения
```

Результат распределяется равномерно по торговым дням (пн–пт) внутри интервала — поэтому пополнение или вывод денег не выглядит как прибыль или убыток. Для месячной доходности используется метод **Modified Dietz**: денежные потоки взвешиваются по количеству оставшихся до конца месяца дней.

### Запуск

Нужен Python 3.9+.

```bash
cd "project 1"

python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

pip install -r requirements.txt

python app.py
```

Откройте **http://127.0.0.1:5001**. База SQLite (`finance.db` рядом с проектом) и все таблицы создаются автоматически при первом старте — ничего дополнительно настраивать не нужно.

### Подключение T-Invest API (опционально)

Без токена приложение работает в ручном режиме: баланс и операции вводятся руками. Чтобы включить синхронизацию:

```bash
cp config.example.py config.py
```

и заполните два поля:

```python
T_INVEST_TOKEN      = "t.ваш_токен"
T_INVEST_ACCOUNT_ID = "2000000000"
```

Токен — в приложении Т-Инвестиции: *Профиль → Настройки → Токен для OpenAPI* (достаточно прав «только чтение»).
ID счёта можно не заполнять сразу: запустите приложение и откройте `http://127.0.0.1:5001/tinkoff-accounts` — эндпоинт вернёт список ваших счётов с их `id`.

`config.py` в `.gitignore` — токен в репозиторий не попадёт. Пока файла нет, кнопки синхронизации возвращают понятную ошибку «config.py не найден», остальное приложение работает.

### Переменные окружения

Все с рабочими значениями по умолчанию, задавать не обязательно:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `FINANCE_DB_PATH` | `finance.db` в папке проекта | Использовать базу в другом месте |
| `FINANCE_PORT` | `5001` | Другой порт |
| `FINANCE_DEBUG` | `1` (включён) | `FINANCE_DEBUG=0` — выключить режим отладки |
| `FINANCE_SECRET_KEY` | dev-ключ | Задать при запуске не на localhost |

```bash
FINANCE_DB_PATH=~/data/finance.db FINANCE_DEBUG=0 python app.py
```

Все они собраны в `settings.py`.

### Разовый импорт операций за год

`/sync-tinkoff` в приложении подтягивает операции только за последние 90 дней. Чтобы залить историю за год:

```bash
python import_operations.py
```

Скрипт добавляет только пополнения и снятия, дубликаты отсекаются по ID операции (`[t:<id>]` в комментарии), так что запускать можно повторно.

### HTTP-эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | Дашборд |
| POST | `/update-balance` | Сохранить баланс на дату |
| POST | `/withdraw` | Записать снятие или пополнение |
| POST | `/delete-entry/<id>`, `/delete-withdrawal/<id>` | Удалить запись |
| GET | `/chart-data` | Заработок по дням за 30 дней |
| GET | `/yearly-chart-data` | 12 месяцев: заработок, после налога, доходность % |
| GET | `/portfolio-snapshot` | Нереализованный P&L по позициям |
| GET | `/portfolio-monthly` | Помесячная доходность топ-5 позиций |
| GET | `/tinkoff-accounts` | Список брокерских счетов (для поиска `account_id`) |
| POST | `/sync-tinkoff` | Синхронизация баланса и операций за 90 дней |

## Dividend Bot (`dividend_bot/`)

### Что делает

- Ежедневно сканирует топ-100 акций MOEX по капитализации (MOEX ISS API, без авторизации)
- Реализует дивидендную стратегию T-7 → T-1: вход за 7 торговых дней до отсечки, выход за 1 день
- Отправляет Telegram-уведомления: новые дивидендные события, напоминания о входе и выходе
- В каждом сообщении — контекст рынка (IMOEX, MA50, MA200) и позиция акции в 52w диапазоне
- Дедупликация сигналов через SQLite, хранение цены входа для расчёта P&L
- Запуск по расписанию (будни 07:00 UTC = 10:00 МСК) или вручную

### Запуск

```bash
cd "project 1/dividend_bot"
pip install -r requirements.txt        # requests, apscheduler

cp config.example.py config.py
```

В `config.py` обязательны два поля — остальное уже заполнено рабочими значениями:

```python
TELEGRAM_TOKEN   = "123456:AA..."      # от @BotFather
TELEGRAM_CHAT_ID = "123456789"         # свой chat_id, например от @userinfobot
```

Там же настраивается стратегия: `BUY_DAYS_BEFORE` / `SELL_DAYS_BEFORE` (T-7 → T-1), `MIN_DAYS_TO_EX`, размер вселенной сканирования `TOP_100_LIMIT`.

Проверка — один прогон здесь и сейчас, без ожидания расписания:

```bash
python main.py --now
```

Постоянная работа (APScheduler, блокирующий процесс):

```bash
python main.py
```

Запускать можно из любой директории — например, `python dividend_bot/main.py --now` из корня репозитория. База `dividend_bot.db` всегда создаётся рядом с кодом бота, в `dividend_bot/`.

### Логика одного прогона

1. **Напоминания о входе** — по сигналам, у которых сегодня `buy_date`. В сообщение подставляются IMOEX и текущая цена, цена входа сохраняется в БД.
2. **Напоминания о выходе** — по сигналам с сегодняшним `sell_date`, с расчётом P&L от сохранённой цены входа.
3. **Поиск новых отсечек** — обход топ-100 тикеров, отбор ближайших дивидендных событий; уже отправленные отсекаются по ключу `TICKER_EXDATE`.

## Ограничения

- Дивидендный бот делает много последовательных запросов к MOEX ISS с паузами `time.sleep(0.3)`, полный скан топ-100 занимает несколько минут.
- Налог считается плоской ставкой 13%, прогрессивная шкала и сальдирование убытков не учитываются.
- Заработок распределяется равномерно по торговым дням интервала, поэтому дневной график — это сглаженная оценка, а не фактическая переоценка по каждому дню. Чем чаще записывается баланс, тем точнее.
- Аутентификации в веб-приложении нет: оно рассчитано на локальный запуск. Перед публикацией наружу задайте `FINANCE_SECRET_KEY`, `FINANCE_DEBUG=0` и закройте доступ на уровне сети.
